# 评论聚合台 · BiliCommentHub

从哔哩哔哩创作中心按内容类型采集评论，保存为 JSON，并通过本地网页浏览、搜索和排序。

## 主要功能

- **五类内容独立采集**：视频、动态、转发动态、专栏、音频分别启用、设置起止页、查看评论总数与页数。
- **两种采集模式**：创作中心按类型和页码采集；仅勾选稿件模式逐稿件采集主评论及可选的楼中楼回复。
- **登录后恢复历史**：扫码或复用保存的登录状态后，自动导入同 UID 的历史导出、恢复匹配的断点，再读取线上稿件。
- **断点续采**：保存各类型页码、已采数据，以及逐稿件模式的主评论游标和回复页码，支持暂停及重启后继续。
- **分类自动导出**：按作者 UID、英文内容分类和稳定稿件 ID 保存，每个稿件一个 JSON，重复导出增量合并。
- **导入合并与导入拆解**：合并 JSON 到当前数据，或将合并文件拆成分类保存的单稿件文件。
- **本地网页预览**：支持稿件与评论搜索、独立排序、图片原图链接、用户主页链接及楼中楼展示。
- **平台凭证保护**：登录信息使用系统安全存储。

采集结果以接口实际返回的数据为准。创作中心接口可返回部分公开稿件列表中不可见的内容；已删除或隐藏内容不保证能补齐标题、正文、封面、IP 属地等信息。

## 构建与启动

### Windows

准备 Rust 的 MSVC 工具链，以及包含 C++ 构建工具和 Windows SDK 的构建环境。在项目根目录执行：

```powershell
cargo build --release --locked
```

构建产物：

```text
target/release/bili-comment-hub.exe
```

也可以通过 Cargo 启动：

```powershell
cargo run --release --locked
```

`web/index.html` 在构建时嵌入程序。修改网页源码后，已有可执行文件不会自动更新其中的网页，需要重新构建。

## 桌面端使用

### 1. 登录与恢复历史

点击左上角的 **扫码登录**，使用哔哩哔哩手机客户端扫码并确认。桌面端不再提供手动粘贴 SESSDATA 的输入框。

账号验证通过后，程序依次执行：

1. 从当前导出目录的 `<登录UID>/` 下读取历史分类 JSON。
2. 合并稿件、评论和回复，恢复列表、统计及网页预览数据。
3. 恢复与当前账号、采集范围和回复选项匹配的断点。
4. 读取线上稿件，更新已有稿件的元数据并保留历史评论。

历史导入只接受作者 UID 与当前登录 UID 一致的内容。重复导入按类型、稿件 ID、评论 ID 和回复 ID 合并；损坏或不匹配的文件会跳过并记入日志。线上稿件为空或读取失败时，已恢复的本地数据仍保留。

下次启动会复用保存的登录状态；登录失效时需要重新扫码。**读取稿件** 可重新触发读取流程。

### 2. 选择采集范围

**创作中心模式**为以下类型分别提供开关、起始页、结束页、总数及“全部”按钮：

| 类型 | 分类目录 | 评论接口类型 |
| --- | --- | --- |
| 视频 | `videos` | `1` |
| 动态 | `dynamics` | `11` |
| 转发动态 | `reposts` | `17` |
| 专栏 | `articles` | `12` |
| 音频 | `audio` | `14` |

- 每页请求 **10 条**，起止页包含在采集范围内。例如 `2–4` 只请求该类型的第 2、3、4 页。
- 起始页默认 `1`，结束页留空表示采集到接口末页。
- **全部** 将该类型恢复为起始页 `1`、结束页留空。
- 未启用的类型不采集，其页码输入禁用。至少启用一种类型才能开始。
- 总数尚未成功获取时显示“未获取”；成功获取的零条记录会显示为零，不与未知状态混淆。

**仅勾选稿件模式**先在列表中勾选稿件，再开始采集。也可以通过 BV 号、av 号或视频链接添加指定视频。此模式不应用创作中心的起止页限制，楼中楼是否采集由“包含楼中楼回复”控制。

### 3. 采集、暂停与继续

- **开始采集**：按当前模式、类型范围和回复选项开始任务。
- **暂停**：保存进度，之后可点击“继续采集”，退出程序后也可恢复。
- **结束**：结束当前任务并清除对应断点，保留已进入当前数据的内容。
- **清除断点**：删除当前任务的断点，下次按当前范围重新开始。
- **清空**：清除当前列表、数据及当前断点；不删除已导出的文件，也不注销保存的登录状态。

断点按账号及任务条件隔离，修改类型、页码或回复选项后不会误用原任务的进度。新断点版本为 `2`，使用每页 10 条；旧版每批 50 条的断点保留文件并提示不兼容，不会自动换算或删除。

默认翻页间隔为 **1800–2400ms**，每次在区间内随机等待。已有自定义配置会保留，不会被新默认值覆盖。触发限流时，每次默认等待 60 秒并显示验证提示。倒计时归零后保持弹窗并检查原采集请求；只有请求成功才自动关闭，仍受限时继续等待。选择“后台继续等”后不再反复弹出，任务仍可暂停或结束。

## 导出与导入

### 自动导出

在设置中开启 **采集完成后自动导出**。默认根目录为应用配置目录下的 `exports`，也可以选择自定义目录。

```text
exports/
└─ <author-uid>/
   ├─ videos/<aid>.json
   ├─ dynamics/<comment-oid>.json
   ├─ reposts/<comment-oid>.json
   ├─ articles/<comment-oid>.json
   └─ audio/<comment-oid>.json
```

用户目录使用**稿件作者 UID**。文件名使用对应接口的稳定评论对象 ID；动态的评论对象 ID 不一定等于 `dynamic_id`，不使用标题命名。

每个文件保存一个稿件及其评论、回复和统计。重复导出会与已有文件增量合并；缺少作者 UID 或稿件 ID 的项目跳过并提示。自动导出不会覆盖无法读取或与当前稿件不匹配的归档文件。

暂停、失败或结束后，若已有可用的部分数据且开启了自动导出，也会尝试保存部分结果。原来的合并文件不会自动搬迁或删除。

### 手动导出与导入

| 操作 | 行为 |
| --- | --- |
| 导出 JSON | 将当前内存数据导出为一个合并 JSON 文件 |
| 导入合并 | 从一个或多个 JSON 中提取稿件与评论，并合并到当前内存数据 |
| 导入拆解 | 将选中的合并 JSON 按作者、类型、稿件 ID 拆成独立文件，保存到设置中的导出目录 |

导入合并支持本工具的文档格式、含 `data.replies` / `data.top_replies` 的接口响应，以及裸评论数组。接口响应可能缺少作者 UID 或稿件元数据，因此能合并显示不代表一定满足分类导出的条件。

导入拆解沿用自动导出的目录结构和增量合并规则，保留源文件。若拆解目标与源文件相同，则跳过该项，避免改写源文件。导入与拆解错误会显示在运行日志中。

## 本地网页

程序默认尝试在 `127.0.0.1:8686` 启动服务，可从右上角状态入口或设置中的 **打开网页** 访问。

- 服务只监听指定端口。端口占用时弹窗报警，不自动换到下一个端口。
- 设置中显示服务实际运行地址。修改端口并保存后，停止、重新启动服务使其生效。
- 网页加载时读取当前数据；采集或导入后，刷新网页获取最新结果。

### 浏览与排序

- 稿件可按标题、编号和评论内容搜索，并按公开状态、内容类型筛选。
- 稿件排序为 **时间倒序 / 时间正序**，默认倒序。缺少发布时间时使用最早评论时间，两者都缺失时置后。
- 评论排序为 **点赞 / 最早 / 最新**，默认点赞；置顶评论始终优先，点赞数相同时优先较新的评论。
- 稿件排序与评论排序互不影响。
- 评论区搜索匹配正文、昵称和楼中楼回复，并高亮结果；支持只看 UP 主和显示楼中楼。
- 评论分批渲染，滚动时追加更多内容。
- 列表封面、详情封面和评论图片可点击打开图片链接；点击列表封面不会切换当前稿件。
- 评论者头像或昵称可打开用户主页。

可用的网页查询参数：

| 参数 | 含义 |
| --- | --- |
| `aid` | 选择指定编号的稿件 |
| `filter` | `all`、`hidden`、`public` |
| `kind` | `all`、`video`、`dynamic`、`article`、`audio`；动态包含转发动态 |
| `vq` | 稿件搜索词 |
| `q` | 评论搜索词 |
| `sort` | 评论排序：`like`、`old`、`new`；旧值 `time` 按最新处理 |

### 数据接口

| 路径 | 内容 |
| --- | --- |
| `/health` | 服务状态，正常返回 `ok` |
| `/api/data.json` | 当前完整文档 |
| `/api/videos` | 稿件列表 |
| `/api/video?aid=123` | 指定编号的单稿件数据 |
| `/api/comments?aid=123&q=关键词` | 评论检索结果；省略 `aid` 时检索全部稿件 |

单稿件接口目前只按 `aid` 查询；不同内容类型的数字 ID 相同时可能存在歧义，完整数据可通过 `/api/data.json` 获取。

## 设置与数据位置

| 设置项 | 默认值或规则 |
| --- | --- |
| 网页端口 | `8686`，设置页允许 `1024–65535` |
| 翻页间隔 | `1800–2400ms`，可设置在 `200–10000ms` 内，上限不能小于下限 |
| 导出目录 | 应用配置目录下的 `exports` |
| 采集完成后自动导出 | 默认关闭 |

Windows 默认应用配置目录：

```text
%APPDATA%/BiliCommentHub/
├─ config.json
├─ exports/<author-uid>/<category>/<object-id>.json
└─ checkpoints/<login-uid>/<task-id>.json
```

`config.json` 保存普通设置和凭证存储信息；`checkpoints` 包含任务进度及已采集的部分数据。导出文件和断点中的评论数据不加密。

可通过绝对路径环境变量指定独立的应用配置目录：

```powershell
$env:BILI_COMMENT_HUB_CONFIG_DIR = 'D:\BiliCommentHubData'
.\target\release\bili-comment-hub.exe
```

自定义的导出目录仍以设置中的路径为准，不会因为更换配置目录自动迁移文件。

### 扫码登录

```powershell
.\target\release\bili-comment-hub.exe login
.\target\release\bili-comment-hub.exe login --no-save
```

默认保存登录凭证；`--no-save` 只验证本次登录，不持久化。命令行不会打印 Cookie。

### 指定视频

```powershell
.\target\release\bili-comment-hub.exe crawl BV1xx411c7mD --out video.json --replies
```

支持多个视频参数，`--replies` 开启楼中楼采集。未指定 `--cookie` 时读取保存的登录信息。

### 创作中心视频评论

```powershell
.\target\release\bili-comment-hub.exe crawl --all --from 1 --to 20 --out comments.json --replies
.\target\release\bili-comment-hub.exe crawl --all --from 21 --to 40 --out comments.json --replies --merge
```

命令行 `--all` 当前采集创作中心的**视频评论**，每页 10 条；五类独立采集请使用桌面端。

| 参数 | 说明 |
| --- | --- |
| `--out` / `-o` | 输出合并 JSON；省略时使用带时间戳的默认文件名 |
| `--all` | 从创作中心采集视频评论，需要有效登录信息 |
| `--from` / `--start-page` | 创作中心起始页，默认 `1` |
| `--to` | 创作中心结束页，`0` 或省略表示到末页 |
| `--replies` | 包含楼中楼回复，命令行默认关闭 |
| `--merge` | `--all` 模式下合并已有输出文件；已有文件无法读取时当前实现会提示后覆盖，重要文件请先备份 |
| `--cookie` | 显式提供登录 Cookie 或 SESSDATA；桌面端无对应输入框 |

`--format` 仅为旧参数兼容保留，会提示忽略；输出始终为 JSON。命令行采集写入单个合并文件，不使用桌面端的分类自动导出或持久化断点。

### 浏览已有文件

```powershell
.\target\release\bili-comment-hub.exe serve --file comments.json --port 8686 --open
```

`web` 是 `serve` 的别名；`--file` 可简写为 `-f`，`--port` 可简写为 `-p`。服务读取指定文档，按 `Ctrl+C` 结束；端口占用时直接报错。

## JSON 格式

文档根节点由 `meta`、`stats`、`videos` 组成，当前 `format_version` 为 `2`。`videos` 是沿用的字段名称，实际可包含五种内容类型。

- 稿件包含 `aid`、`bvid`、`kind`、`comment_type`、作者、标题、链接、封面、发布时间及 `comments`。
- 动态等内容还可包含正文、图片、`dynamic_id`、转发原文及内容本身的赞评转信息。
- 主评论包含 `rpid`、用户信息、正文、点赞、时间、IP 属地、图片、置顶标记及 `replies`。
- 回复包含自己的 `rpid`、用户信息、正文、时间、点赞、图片和父级 ID。

缺失字段可能是接口未返回、内容不可访问或旧文件未记录。部分非公开稿件无法通过公开评论接口补齐 IP 属地；未能获取时保留空值。

## 源码结构

```text
src/
├─ main.rs          # 桌面回调、工作线程、配置与命令行
├─ bili.rs          # B 站请求、分页、评论解析与信息补全
├─ collection.rs    # 五类采集范围和每页条数
├─ checkpoint.rs    # 任务身份、进度保存与恢复
├─ export.rs        # JSON 导入、导出、分类归档与拆解
├─ model.rs         # 稿件、评论、回复、合并及统计
├─ qrlogin.rs       # 扫码登录
├─ secure.rs        # 平台凭证保护
└─ web.rs           # 本地 HTTP 服务
ui/app.slint        # 桌面界面
web/index.html      # 内嵌网页
build.rs            # Slint 界面构建
```

项目包含配置、断点、导入导出、端口和界面组件相关测试。开发者可自行执行：

```powershell
cargo test --locked
```

## 使用说明

请仅处理你有权访问的数据，合理设置请求间隔。接口数据和可访问范围可能随 B 站调整而变化，降低频率或等待重试不保证能够绕过限制。

导出文件可能包含评论者 UID、昵称和评论内容；分享或公开前请自行检查。登录凭证、配置文件及系统凭据库记录不应随评论文件一并分享。
