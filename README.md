# BiliArchive

> 归档统一使用 **Bili Archive v1**。评论按类型、每稿件一份 JSON 持续自动归档，消息与附件同样自动保存。支持自动读取当前账号现有的新版归档；支持通过账号菜单导入新版 JSON、归档目录或离线资料包；不提供拆解或旧归档转换。格式、目录和资源策略见 [新版归档说明](docs/archive-v1.md) 和 [JSON Schema](schemas/archive-v1.schema.json)。

私信图片与其他消息附件（音频、文件等）始终启用离线保存，不提供关闭开关；头像、主题封面、评论/动态配图在设置中分别启用，默认关闭。保存设置后可点击“处理资源”，账号消息也可继续使用“处理附件”。未启用资源不计入待处理。单人点赞头像使用正常尺寸，多人时才叠放。


从哔哩哔哩创作中心按内容类型采集评论，保存为 JSON，并通过本地网页浏览、搜索和排序。

## 主要功能

- **五类内容独立采集**：视频、动态、转发动态、专栏、音频分别启用、设置起止页、查看评论总数与页数。
- **两种采集模式**：创作中心按类型和页码采集；仅勾选稿件模式逐稿件采集主评论及可选的楼中楼回复。
- **登录后恢复历史**：扫码或复用保存的登录状态后，自动读取同 UID 的已有新版归档、恢复匹配的断点，再读取线上稿件。
- **断点续采**：保存各类型页码、已采数据，以及逐稿件模式的主评论游标和回复页码，支持暂停及重启后继续。
- **本地网页预览**：独立进程在本机提供网页、API 和图片，随桌面关闭。支持稿件与评论搜索、独立排序、图片原图链接、用户主页链接及楼中楼展示。
- **归档预缓存**：设置中默认开启。关闭后，桌面只常驻稿件列表和统计，网页按所选稿件、消息分类或会话读取磁盘。首次读取和全局搜索可能较慢。
- **本地归档线程数**：留空为自动，最多使用 4 个线程。可设为 1–16，1 为串行，保存后从下一次本地归档读取或离线包导入生效。此设置用于并行读取、解包和导入解析，线上采集仍遵守翻页间隔。
- **平台凭证保护**：登录信息使用系统安全存储。

采集结果以接口实际返回的数据为准。创作中心接口可返回部分公开稿件列表中不可见的内容；已删除或隐藏内容不保证能补齐标题、正文、封面、IP 属地等信息。

## 构建与启动

桌面版同一登录会话只运行一个实例。重复打开会提示「BiliArchive 已在运行」，已有窗口和网页预览继续工作。应用退出后可重新启动。网页预览子进程和命令行命令独立运行。

### GitHub Actions 自动构建

推送到 `main`、向 `main` 提交 Pull Request，或在 Actions 页面手动运行 **Windows build**，会自动执行测试并生成 Windows x64 Release 程序。

进入 [Windows build](https://github.com/LinMoyuu/BiliArchive/actions/workflows/windows-build.yml)，打开成功的运行记录，在 **Artifacts** 下载 `biliarchive-windows-x64`，解压后运行 EXE。构建产物保留 14 天。

工作流使用 `Cargo.lock` 固定依赖版本并缓存依赖；测试或构建失败时不会上传可执行文件。

### Windows

准备 Rust 的 MSVC 工具链，以及包含 C++ 构建工具和 Windows SDK 的构建环境。在项目根目录执行：

```powershell
cargo build --release --locked
```

构建产物：

```text
target/release/biliarchive.exe
```

也可以通过 Cargo 启动：

```powershell
cargo run --release --locked
```

`web/index.html` 在构建时嵌入程序。修改网页源码后，已有可执行文件不会自动更新其中的网页，需要重新构建。

## 桌面端使用

### 1. 登录与恢复历史

点击右上角的 **账号登录**，使用哔哩哔哩手机客户端扫码并确认。登录后入口显示头像和用户名，点击可查看 UID，并通过“切换账号”重新扫码；任务执行期间不能切换账号。头像加载失败使用默认头像，不影响登录。桌面端不再提供手动粘贴 SESSDATA 的输入框。

账号验证通过后，程序依次执行：

1. 从当前导出目录的 `<登录UID>/` 下读取历史分类 JSON。
2. 合并稿件、评论和回复，恢复列表、统计及网页预览数据。
3. 恢复与当前账号、采集范围和回复选项匹配的断点。
4. 读取线上稿件，更新已有稿件的元数据并保留历史评论。

历史读取只接受作者 UID 与当前登录 UID 一致的内容。已保存数据按类型、稿件 ID、评论 ID 和回复 ID 合并；损坏或不匹配的文件会跳过并记入日志。线上稿件为空或读取失败时，已恢复的本地数据仍保留。

下次启动会复用保存的登录状态；登录失效时需要重新扫码。采集范围标题行的 **读取稿件** 位于“全选 / 反选”左侧，仅在“仅勾选稿件”模式显示，与旁边按钮使用相同的紧凑文字样式，可重新触发读取流程。

### 2. 选择采集范围

**创作中心模式**为以下类型分别提供开关、起始页、结束页、总数及“全部”按钮：

| 类型 | 分类目录 | 评论接口类型 |
| --- | --- | --- |
| 视频 | `videos` | `1` |
| 动态 | `dynamics` | `11` |
| 转发动态 | `reposts` | `17` |
| 专栏 | `articles` | `12` |
| 音频 | `audio` | `14` |

- 每页请求 **10 条**，起止页包含在采集范围内。例如 `2–4` 只请求该类型的第 2、3、4 页。
- 每次启动或切换账号，五类开关先全部关闭、页码留空。登录后检测全部五类的评论总数，正数类型自动启用，并恢复保存的自定义页码、按上限纠正；没有自定义值时填写 `1` 到末页。
- 已知零条时关闭该类型、清空显示页码，开关、输入框与“全部”均禁用。未知总数也不能填写，可点击“未获取 · 点击重试”重新获取。查询失败不视为零条，已有成功结果会保留。
- 本次账号会话内手动关闭的类型不会因刷新重新启用，手动修改的页码也不会被普通刷新覆盖；重启或切换账号后重新从关闭状态检测。初始化或零条时界面暂时留空不会擦掉保存的页码偏好。
- **全部** 将当前可用、已启用类型设为 `1` 到已知末页。按钮与输入框均为 43×24px、10px 字号，页码标题使用相同字号与高度对齐。
- 起止页超过该类型已知总页数时自动修正到末页。未启用的类型不采集，页码输入禁用；至少启用一种类型才能开始。

**仅勾选稿件模式**先在列表中勾选稿件，再开始采集。也可以通过 BV 号、av 号或视频链接添加指定视频。此模式不应用创作中心的起止页限制，楼中楼是否采集由“包含楼中楼回复”控制。列表按发布时间倒序，兼容秒、毫秒和日期文本；没有发布时间时使用最早评论时间，仍无时间的放在末尾，相同时间保持原顺序。列表显示视频 BV/av、专栏 cv、音频 au、动态或转发动态 ID，不将无 BV 号的内容一律识别为视频；排序不改变勾选对应的稿件。

### 3. 采集、暂停与继续

启动时读取本地历史稿件和本地断点期间，暂停、结束按钮禁用；本地读取完成后恢复采集控制。该阶段不会因为点击控制按钮删除采集断点。

- **开始采集**：按当前模式、类型范围和回复选项开始任务。
- **暂停**：保存进度，之后可点击“继续采集”，退出程序后也可恢复。
- **结束**：结束当前任务并清除对应断点，保留已进入当前数据的内容。
- **清除断点**：删除当前任务的断点，下次按当前范围重新开始。

断点按账号及任务条件隔离，修改类型、页码或回复选项后不会误用原任务的进度。新断点版本为 `3`，使用每页 10 条；旧版每批 50 条的断点保留文件并提示不兼容，不会自动换算或删除。

默认翻页间隔为 **1800–2400ms**，每次在区间内随机等待。已有自定义配置会保留，不会被新默认值覆盖。触发限流时，每次默认等待 60 秒并显示验证提示。倒计时归零后保持弹窗并检查原采集请求；只有请求成功才自动关闭，仍受限时继续等待。选择“后台继续等”后不再反复弹出，任务仍可暂停或结束。风控弹窗显示剩余等待秒数，归零后显示正在检查恢复；右上角不再展示任务状态或进度条。

两个工作区的“结果预览”统一使用统计卡片，运行日志占用剩余高度并可独立滚动。消息归档显示回复我的、@我的、赞通知、私信、粉丝团五项数量；赞通知按通知条数统计，私信不含粉丝团，均统计当前账号已加载的全部归档，零值仍显示。消息内容浏览、搜索与排序请使用网页预览。

## 数据保存与手动导出

评论采集每页完成后，按账号、作者和英文类型增量保存，每个稿件一个 Bili Archive v1 JSON。归档成功后才推进断点。消息与附件按账号、分类和会话自动保存，并保留独立采集报告。网页账号菜单显示上次成功保存采集数据的时间。

默认导出根目录为应用配置目录下的 `exports`，可在设置中修改。自动读取当前导出目录中的新版分类评论归档，已有文件留在原处；支持通过账号菜单导入新版 JSON、归档目录或离线资料包；不提供拆解或旧格式转换。

两工作区共用采集控制和深色日志面板：空闲时显示开始或继续，执行当前采集或资源任务时显示暂停和结束；本地读取和不可取消的后台操作仅显示处理状态。消息页与评论页使用同样高度的统计面板。

### 评论自动归档目录

Windows 默认保存到 `%APPDATA%/BiliArchive/exports`。继续读取原 `BiliCommentHub` 目录中的归档时，在设置里选中原导出目录。

```text
archive-v1/<account_uid>/comments/<author_uid>/
  videos/<oid>.json
  dynamics/<oid>.json
  reposts/<oid>.json
  articles/<oid>.json
  audio/<oid>.json
```

使用每稿件一个文件，避免每次补采重写整类数据；重复采集按评论与回复 ID 合并。只重写当前页涉及的稿件，结束前补存已补全的资料。文件写入失败时停止并保留原断点，不跳页、不误报完成；已有损坏文件或账号不匹配文件不覆盖。暂停或结束保留已归档内容。未恢复旧字段读取兼容，不批量改写用户旧文件。

## 本地网页

程序默认尝试在 `127.0.0.1:8686` 启动服务，可从设置中的 **打开网页** 访问，也可点击应用底栏最左侧的“预览网页服务运行中”打开实际运行地址。未运行时底栏显示“预览网页服务未运行”，点击打开设置；两种状态均无下划线，与设置里的服务状态同步。启动或失败信息会记入日志，重复打开已运行的网页不增加“预览已在运行”日志；顶部账号信息不受服务状态影响。

- 服务只监听指定端口。端口占用时弹窗报警，不自动换到下一个端口。
- 设置中显示服务实际运行地址。修改端口并保存后，停止、重新启动服务使其生效。
- 网页加载时读取当前数据；采集后，刷新网页获取最新结果。

### 浏览与排序

- 稿件可按标题、编号和评论内容搜索，并按公开状态、内容类型筛选。
- 稿件排序为 **时间倒序 / 时间正序**，默认倒序。缺少发布时间时使用最早评论时间，两者都缺失时置后。
- 评论排序为 **点赞 / 最早 / 最新**，默认点赞；置顶评论始终优先，点赞数相同时优先较新的评论。
- 稿件排序与评论排序互不影响。
- 评论区搜索匹配正文、昵称和楼中楼回复，并高亮结果；支持只看 UP 主和显示楼中楼。
- 评论分批渲染，滚动时追加更多内容。
- 列表封面、详情封面和评论图片可点击打开图片链接；点击列表封面不会切换当前稿件。
- 评论者头像或昵称可打开用户主页。

可用的网页查询参数：

| 参数 | 含义 |
| --- | --- |
| `aid` | 选择指定编号的稿件 |
| `filter` | `all`、`hidden`、`public` |
| `type` | `all`、`video`、`dynamic`、`article`、`audio`；动态包含转发动态 |
| `vq` | 稿件搜索词 |
| `q` | 评论搜索词 |
| `sort` | 评论排序：`like`、`old`、`new`；旧值 `time` 按最新处理 |

### 数据接口

| 路径 | 内容 |
| --- | --- |
| `/health` | 服务状态，正常返回 `ok` |
| `/api/comments/archive.json` | 规范归档 JSON 下载 |
| `/api/comments/data.json` | 评论页面数据，支持 `view=list` 和 `view=search&q=关键词` |
| `/api/comments/posts` | 稿件列表 |
| `/api/comments/posts/123` | 指定编号的单稿件数据 |
| `/api/comments/search?aid=123&q=关键词` | 评论检索结果；省略 `aid` 时检索全部稿件 |

网页稿件列表支持按时间或评论数量排序。选择「评论最多」或「评论最少」时优先使用平台计数，缺失时使用本地主评论和楼中楼回复总数。

单稿件接口支持 `comment_type`，可区分数字 ID 相同的不同类型稿件。稿件评论的页面地址是 `/comments`，消息归档是 `/messages`。根地址跳转到 `/comments` 并保留查询参数和稿件锚点。

## 设置与数据位置

| 设置项 | 默认值或规则 |
| --- | --- |
| 网页端口 | `8686`，设置页允许 `1024–65535` |
| 翻页间隔 | `1800–2400ms`，可设置在 `200–10000ms` 内，上限不能小于下限 |
| 导出目录 | 应用配置目录下的 `exports` |

Windows 默认应用配置目录：

```text
%APPDATA%/BiliArchive/
├─ config.json
├─ exports/archive-v1/<account-uid>/comments/<author-uid>/<category>/<object-id>.json
└─ checkpoints/
   ├─ <login-uid>/<task-id>.json
   └─ messages/<account_uid>.json
```

`config.json` 保存普通设置和凭证存储信息；`checkpoints` 包含任务进度及已采集的部分数据。导出文件和断点中的评论数据不加密。

可通过绝对路径环境变量指定独立的应用配置目录：

```powershell
$env:BILI_COMMENT_HUB_CONFIG_DIR = 'D:\BiliArchiveData'
.\target\release\biliarchive.exe
```

要继续使用原有的配置、登录状态、离线资料库和断点，可用此环境变量显式指定整个应用数据目录，例如 `%APPDATA%/BiliCommentHub` 对应的绝对路径。网页预览继承同一个环境变量。自定义导出目录以当前配置中的路径为准。

### 扫码登录

```powershell
.\target\release\biliarchive.exe login
.\target\release\biliarchive.exe login --no-save
```

默认保存登录凭证；`--no-save` 只验证本次登录，不持久化。命令行不会打印 Cookie。

### 指定视频

```powershell
.\target\release\biliarchive.exe crawl BV1xx411c7mD --out video.json --replies
```

支持多个视频参数，`--replies` 开启楼中楼采集。未指定 `--cookie` 时读取保存的登录信息。

### 创作中心视频评论

```powershell
.\target\release\biliarchive.exe crawl --all --from 1 --to 20 --out comments.json --replies
.\target\release\biliarchive.exe crawl --all --from 21 --to 40 --out comments.json --replies --merge
```

命令行 `--all` 当前采集创作中心的**视频评论**，每页 10 条；五类独立采集请使用桌面端。

| 参数 | 说明 |
| --- | --- |
| `--out` / `-o` | 输出合并 JSON；省略时使用带时间戳的默认文件名 |
| `--all` | 从创作中心采集视频评论，需要有效登录信息 |
| `--from` / `--start-page` | 创作中心起始页，默认 `1` |
| `--to` | 创作中心结束页，`0` 或省略表示到末页 |
| `--replies` | 包含楼中楼回复，命令行默认关闭 |
| `--merge` | `--all` 模式下合并已有输出文件；已有文件无法读取时当前实现会提示后覆盖，重要文件请先备份 |
| `--cookie` | 显式提供登录 Cookie 或 SESSDATA；桌面端无对应输入框 |

`--format` 仅为旧参数兼容保留，会提示忽略；输出始终为 JSON。命令行采集写入单个合并文件，不使用桌面端的持久化断点。

### 浏览已有文件

```powershell
.\target\release\biliarchive.exe serve --file comments.json --port 8686 --open
```

`web` 是 `serve` 的别名；`--file` 可简写为 `-f`，`--port` 可简写为 `-p`。服务读取指定文档，按 `Ctrl+C` 结束；端口占用时直接报错。

## JSON 格式

文档根节点由 `meta`、`stats`、`videos` 组成，当前 `format_version` 为 `2`。`videos` 是沿用的字段名称，实际可包含五种内容类型。

- 稿件包含 `aid`、`bvid`、`type`、`comment_type`、作者、标题、链接、封面、发布时间及 `comments`。
- 动态等内容还可包含正文、图片、`dynamic_id`、转发原文及内容本身的赞评转信息。
- 主评论包含 `rpid`、用户信息、正文、点赞、时间、IP 属地、图片、置顶标记及 `replies`。
- 回复包含自己的 `rpid`、用户信息、正文、时间、点赞、图片和父级 ID。

缺失字段可能是接口未返回、内容不可访问或旧文件未记录。部分非公开稿件无法通过公开评论接口补齐 IP 属地；未能获取时保留空值。


## 使用说明

请仅处理你有权访问的数据，合理设置请求间隔。接口数据和可访问范围可能随 B 站调整而变化，降低频率或等待重试不保证能够绕过限制。

导出文件可能包含评论者 UID、昵称和评论内容；分享或公开前请自行检查。登录凭证、配置文件及系统凭据库记录不应随评论文件一并分享。

稿件 JSON 的内容类型字段统一为 `type`，不再读取旧 `kind` 字段；网页筛选参数同样使用 `type`。旧格式文件不读取，请重新采集。


## 账号消息采集与归档

桌面顶部通过产品名称菜单切换「稿件评论」和「消息归档」。账号消息支持私信（包括未关注人及可访问的非系统用户会话）、粉丝团、收到的赞、回复我的和 @我的；排除系统会话和系统通知。不提供发消息、删除、点赞或主动确认已读操作。

- 使用同一登录账号、代理和请求间隔，默认间隔 1800～2400 ms；风控等待每轮 60 秒，原请求成功后才关闭等待提示。
- 登录后只读取本地归档，线上采集需要手动点击“开始采集账号消息”或“继续采集（断点）”。日期留空为全部可用历史，界面显示 `yyyy/MM/dd`，内部日期仍使用 `YYYY-MM-DD`，结束日期包含当天。接口可能限制历史范围，不能据此恢复服务端已不再返回的记录。
- 支持暂停、继续与结束。暂停保留断点，结束清除当前消息任务断点，但保留已保存的消息和附件。消息任务与稿件任务互斥，本地读取不可暂停或结束。
- 私信保存双方消息、原始内容和撤回状态；未知类型保留原始字段。超大消息 ID 使用字符串。重复采集合并去重，附件失败可通过继续采集重试。
- 图片、表情、语音和明确的文件附件自动下载；分享卡片保留封面和原链接，不下载其指向的整部视频或文章。附件下载不携带登录 Cookie。
- 桌面显示当前账号五类消息统计，采集和本地读取时同步更新。网页 `/messages` 提供独立消息浏览和已下载图片/音频展示。
- 当前账号的已有新版归档会自动读取，可通过离线资料包备份和转移。

归档放在当前导出根目录内，目录名均为英文或数字：

```text
exports/archive-v1/<account_uid>/messages/
  private/user_<uid>.json
  private/group_<id>.json
  likes.json
  replies.json
  mentions.json
  # 资源位于 archive-v1/resources/<account_uid>/
```

消息断点独立保存在用户数据目录的 `checkpoints/<library_id>/messages/v2/<account_uid>.json`。切换导出目录或采集条件会建立新的消息任务。消息和评论均使用 `format: "bili-archive"`、`version: 1`，具体字段以新版归档说明为准。消息与附件是普通归档文件，可能包含私密对话内容。

本地消息接口：`GET /api/messages/summary`、`GET /api/messages/items?type=all&session=&q=&order=new&offset=0&limit=50`、`GET /api/messages/attachments/<id>`。分类为 `private/groups/likes/replies/mentions`，排序为 `new/old`；`type=likes` 另支持 `likes_desc/likes_asc`，先搜索、排序再分页，单页最多 200 条；接口只允许同源读取，附件按登记 ID 访问。

收到的赞可能是平台聚合后的通知，按通知时间筛选并保留原始用户列表和计数，不据此虚构逐次点赞事件。

消息网页轻量检查：`node tests/messages-web.cjs`。Rust 模拟响应与临时目录测试包含在 `cargo test --locked` 中；未运行 Rust 测试时，不能将语法检查视为测试通过。


### 点赞用户明细

「收到的赞」通知列表只包含少量示例用户。采集点赞时会继续调用 `/x/msgfeed/like_detail`，按通知 ID、页码和 `last_mid` 遍历接口可访问的用户明细；每页保存后才推进断点，暂停后从下一页继续，重复页或请求失败会保留数据并标为未完成。

每条点赞通知增加 `like_count`（通知报告数量）、`like_users`（用户 UID、昵称、头像、点赞时间与原始数据）及 `like_detail`（`pending/partial/finished` 状态与错误信息）。旧消息归档缺少这些字段时视为待补采；通知摘要刷新不会清空已保存的明细。新任务会重新遍历并合并用户，历史归档不会因用户取消点赞而被删除。匿名用户依据原始记录区分，不会全部合并为一个用户。

桌面「赞通知」统计卡显示已归档的通知条数。网页点击赞通知进入内容区内的「点赞详情」，独立搜索、排序和翻页；返回后恢复通知列表位置。通知数和用户数分别统计，界面显示通知报告数量、已归档用户数及采集状态。日期范围用于筛选通知，选中通知的明细不会再按摘要日期截断。

`finished` 仅表示接口已返回末页；通知计数与已归档用户数不一致时会明确提示，不能保证恢复平台未提供的历史用户。大量点赞会增加采集时间，仍遵守当前请求间隔及风控等待设置。

本地新增 `GET /api/messages/likes?card_id=<id>&q=&order=new&offset=0&limit=50`，单页最多 200 位；通知列表接口返回 `like_users_count`，完整用户列表通过此分页接口读取，合并 JSON 导出仍保存全部明细。目录保持不变。


### 粉丝团独立采集

普通「私信（含未关注人）」与「粉丝团」分别选择。粉丝团在启动应用或切换账号后默认不勾选；勾选时弹出“粉丝团消息量可能较大，采集可能需要很久。是否继续勾选？”，只有点击「继续勾选」才开启。取消、关闭或点击遮罩均不勾选，关闭已勾选开关无需再次确认。

可单独采普通私信、单独采粉丝团，或两者同时采。未选择粉丝团时，不查询其会话分类、不读取其历史消息，也不补下载粉丝团附件；已有断点中的粉丝团会话同样受此限制。

桌面的「私信」和「粉丝团」统计分别显示普通用户消息与群消息数量。网页将两类会话统一放在「私信」中，粉丝团会话排在最前，两组各自按最近消息时间倒序；没有粉丝团时不显示其分组标题。两类统计和采集开关仍独立，未勾选采集不会删除或隐藏已有粉丝团归档。

查询与采集使用独立分类 `groups`，统计接口新增 `counts.groups`；`counts.private` 只统计普通私信。本地消息列表的 `category` 表示查看分类，存储字段 `type` 仍为 `private`，会话类型仍为 `session_type: 1/2`。原有 `private/user_<uid>.json`、`private/group_<id>.json` 无需迁移，自动读取与手动导出继续保留两类消息。

消息断点存放在 `checkpoints/<library_id>/messages/v2/`，稿件断点存放在 `checkpoints/<library_id>/<login-uid>/`。旧路径状态在归属验证后迁移并备份，不静默覆盖新路径的已有记录。


### 账号消息日期范围

点击开始日期或结束日期打开日历，可用年份列表、月份选择器和日期格选择日期。「确定」写入所选日期，「取消」或 Escape 保留原值，「清空」恢复不限。若开始日期晚于结束日期，日历会提示，保留原有范围。

默认开始日期不限，结束日期为本地当天。结束日期处于自动状态时，在进入消息归档或开始采集前更新；手动确认或清空结束日期后保留该选择。切换账号会恢复默认值并关闭日历。界面显示 `yyyy/MM/dd`，内部仍使用 `YYYY-MM-DD`，结束日期包含当天全天。采集及本地处理期间无法修改日期。

### 网页顶部账号与消息侧栏

应用与网页的产品菜单紧贴名称和箭头所在行展开。应用右上角账号入口按头像、昵称、箭头的内容宽度排布，取消入口背景；昵称过长时省略，与设置按钮保留紧凑间隔。

「我的评论」还可按回复数、被赞数和发布时间正序或倒序排列。优先使用评论详情的原站计数，缺失时分别使用已归档回复数和点赞通知中的最大计数，卡片会标明来源。发布时间或被赞数未知的记录排在末尾。

### 网页消息统计与折叠

消息归档顶部与评论页使用相同的统计样式，显示当前账号全量归档的回复、@、赞通知和私信数量；私信包含粉丝团并标明其中数量，赞按通知条数统计。搜索、分页和折叠不改变这些全局数字。正文保留附件统计；窄屏将消息统计放在顶部第二行并允许横向滚动，避免挤压产品名称和账号。

“回复我的”和“@我的”支持 **平铺 / 按用户 / 按主题**，默认平铺，两类分别记住模式。分组针对全部匹配消息，而不是当前消息页：外层每批 50 项（分组或独立消息），接近底部自动追加下一批；分组初始折叠，展开先加载 50 条，接近组尾继续追加。两层均保留“加载更多”按钮；失败后暂停自动加载，可手动重试，空页或末页停止。追加保留已有消息、展开和滚动位置；全局最多同时发出两个分页请求，隐藏工作区暂停新的自动加载。切换产品工作区保留状态；修改分类、会话、搜索、排序、模式或刷新会重置列表并忽略旧响应。

按用户使用发送者 UID，不因同名合并；缺少有效 UID 时独立显示。按主题从原始通知的原生地址、公开链接及明确的目标 ID 识别视频、动态和专栏。视频 BV/AV 本地转换后统一归组，动态链接与 opus 链接统一归组，忽略分 P 和评论定位参数；同主题直接评论与评论回复合并，保留每条通知。不凭标题或正文相同猜测目标，不同类型的相同数字 ID 不合并，冲突或无法确认目标的通知保持独立。分组与组内消息均支持时间正序/倒序，缺少时间置后。

新增只读接口 `GET /api/messages/groups?type=replies&group_by=user&q=&order=new&offset=0&limit=50`，仅支持 `replies/mentions` 和 `user/video`。返回 `total`（外层项数）、`total_items`（匹配消息条数）及 `groups` 摘要；独立条目携带原消息。组内明细沿用 `/api/messages/items`，额外传入相同的 `group_by` 和返回的 `group_key`，其他筛选条件保持一致。不带分组参数的原接口行为不变，所有接口沿用同源和禁止缓存限制，不改变归档格式，也不增加线上采集请求。

新增检查 `node tests/message-groups-web.cjs` 覆盖顶部全局统计、惰性展开、独立组分页、重试、转义、模式记忆、过期响应与账号重置；Rust 检查覆盖分组识别、跨分页、BV/av 映射、非视频保留及接口分页。本次未执行本地 Rust 编译或 Rust 测试。

### 回复与 @ 次数排名

网页“回复我的”和“@我的”在按用户或按主题分组时，可选择“回复次数最多 / 最少”或“@次数最多 / 最少”，保留时间倒序与正序；默认仍为平铺、时间倒序。次数按当前分类和搜索条件匹配的归档通知条数计算，先对完整分组排序再分页；独立条目按 1 条参与，次数相同按最新通知时间倒序，再按稳定分组键排列，未知时间排在相同次数的已知时间之后。

`node tests/message-avatars-web.cjs` 验证跨分类复用、分页自带头像、统一安全地址/默认头像回退，以及已知资料不额外查询。`node tests/private-profiles-web.cjs` 同时检查冷查询期间已知缓存立即显示与当前聊天补全优先级。


私信面板中的会话列表和聊天背景铺满左、右及底部边缘，仅保留面板外框；工具栏和消息内容自身仍保留阅读间距，窄屏使用相同规则。输入搜索词时，右侧切换为跨会话结果列表，显示来源会话名称，搜索不受当前选中会话限制。清空搜索恢复原会话及阅读位置；点击具体会话或“所有私信”会清空搜索词并打开对应完整归档。已有聊天 DOM、展开状态和历史缓存保留。

`node tests/private-global-search-web.cjs` 检查普通私信/粉丝团跨会话搜索、来源标签、空结果及恢复原聊天。点赞详情检查覆盖自动追加、原内容保留、重复用户、空页、失败手动重试、搜索排序重置、隐藏暂停及关闭/账号切换后的迟到响应。仅调整本地网页、相关检查与文档，不修改接口或归档格式，不执行 Rust 编译或提交推送。


### 归档格式与任务报告

当前归档规范和十类示例见 [Bili Archive v1](docs/archive-v1.md)。已有分类评论位于 `archive-v1/<账号UID>/comments/<作者UID>/<英文分类>/<稿件ID>.json`；消息位于 `archive-v1/<账号UID>/messages/`。评论和消息均持续自动归档；手动导出用于另存合并文件。旧格式不兼容，不提供转换入口；已有文件保留不动。

每次消息开始／继续生成独立报告 `archive-v1/<账号UID>/reports/<run_id>.json`，整轮异常不复制到各个归档文件。消息日志实时记录风控、超时、分页异常及其重试和最终结果。详见 [任务报告规范](docs/archive-v1.md#任务报告与实时状态)。

`node tests/archive-v1-contract.cjs` 检查十类示例、资源与报告规范、共享界面组件及移除功能的边界。Rust 测试源码另覆盖归档往返和模拟请求；语法检查不等于 Rust 编译或运行测试。

### 点赞明细分页停滞

分页异常按文末“消息分页异常与 NG”规则处理：首次延后，正常采集结束后补试一次，失败标记 NG；风控和网络异常继续使用原等待规则。

### 收到的赞数量排序

网页“收到的赞”支持时间倒序、时间正序、点赞最多和点赞最少，默认时间倒序。数量使用通知报告的 `like_count`，而非已归档点赞用户数；同赞数按最新已知时间在前，未知时间在后，仍相同时保持原顺序。服务端在搜索后、分页前排序，连续加载保持一致。

该分类的排序独立保存，切换分类和工作区仍保留；刷新网页或切换账号恢复默认。改变排序保留搜索并重新从第一页读取，点赞详情中的用户列表仍独立按时间排序。

### 消息分页异常与 NG

消息归档的通知流、点赞用户明细、私信会话列表和私信/粉丝团历史使用同一规则：首次分页异常先保存已读取内容与有效断点，跳过当前目标继续其他来源；正常消息采集结束后、附件处理前集中补试。每个异常页只补试一次，仍不能前进则标记 NG，不再循环请求。正常结束页不会因用户数少于通知计数而标记异常。

NG 与延后补试记录独立保存在用户数据目录的 `ng/<library_id>/messages/v1/<uid>.paging.json`，与 `checkpoints/` 完全分开，按账号和导出目录隔离；结束普通任务不会删除 NG。普通继续采集跳过已有 NG；消息操作区的“重试NG项（数量）”只补采当前账号、当前导出目录的 NG，沿用各项原日期范围和断点，每项重新获得一次补试机会。成功恢复后继续后续分页，失败保留 NG。

暂停、结束或关闭程序不启动后续补试，未处理队列保留；取消中的请求不消耗失败次数。风控和网络异常仍使用原等待规则，不计入分页补试次数；分页补试不增加额外等待，但每次请求仍遵守配置的翻页间隔。日志与独立采集报告显示延后、集中补试、恢复、NG 和跳过已有 NG，存在未解决项时显示部分完成。旧异常文本不会自动转为 NG，原始消息与归档 JSON 格式不变。

旧断点目录内的 `.paging.json` 在读取对应账号、导出目录时自动迁入独立 NG 目录；校验写入成功后才删除旧文件，已有新记录优先，迁移失败保留原文件。普通采集和 NG 补采的临时任务进度仍属于断点，NG 标记不随断点清理删除。

“继续采集（断点）”仅在存在非 NG 的未完成采集或待补试队列时显示；只有 NG 或附件待处理时显示“开始采集”，NG 数量单独显示在“重试NG项”按钮中。开始采集会建立新一轮普通任务，NG 记录仍保留并跳过。

网页展开“收到的赞”后，若被赞内容是评论，顶部标题链接优先使用 `native_uri` 中的二级评论、anchor 或根评论定位信息，缺少时使用被赞评论的 `item_id`；视频、动态、专栏评论均保留评论锚点，动态同时打开评论区。支持应用侧 `comment/detail` 与其 `enterUri` 主题路由，无法可靠定位时仍可打开原主题。标题和封面分开跳转，封面继续打开原图，不修改归档数据。

### 应用工作区面板布局

稿件评论与消息归档共用主体布局和卡片外壳：左右边距 16px、上下边距 14px、左列 372px、列间距 14px；操作卡片到结果预览为 8px，结果预览到日志为 14px。外层面板统一 14px 圆角、边框和阴影；采集与导出卡片高 166px，按钮到卡片底边为 8px、结果统计高 101px，运行日志填满剩余高度。长状态文字在卡片内省略，消息侧滚动区保留卡片内边距，日期弹窗独立显示。两个工作区持续保留各自界面实例，切换不重建输入或停止当前任务。

应用切换工作区只切换保留的界面实例，并合并发送轻量后台检查；已加载的同账号同目录数据直接使用现有统计，不在界面线程扫描存档、读取断点或 NG。首次读取在后台进行，切换不重启或停止采集。两端的卡片标题使用共用标题行，消息侧采集范围标题固定在滚动区外；按钮、开关标签和日期文字按所属控件居中对齐。

应用右上角仅保留账号和设置，不再显示任务状态及进度条；消息归档“采集与导出”标题旁不再重复显示状态。运行日志、底部状态、暂停/结束及风控等待弹窗保持可用，内部采集进度仍供等待和恢复判断使用。

读取稿件不再逐页打印“读取稿件第 N 页，获得 N 条”，也不再打印“共 N 个稿件，勾选后点开始采集”的汇总日志；列表、统计、底部读取完成提示和异常日志仍正常更新。两个工作区同步收紧操作按钮下方留白，释放高度由日志面板使用。


## 离线账号与资料包

点击右上角账号菜单，选择“导入离线资料”或导入目录，可读取 Bili Archive v1 JSON、账号归档目录及本应用导出的 `.zip` 资料包。没有有效登录会话也可浏览、搜索和导出本地内容。导入后资料保存在用户数据目录的 `libraries/<library_id>/`，账号菜单可切换已导入账号；重启会恢复上次选择，无需再次导入。缺少账号 UID 的公开评论归档作为公共资料读取。

离线预览优先显示本地图片，缺失时可自动显示归档中已有的公开 B 站图片，预览本身不写入归档。离线状态也可以显式重试公开图片、附件等资源下载；账号消息采集和分页 NG 重试仍需在线验证。公开资源地址可能失效或要求鉴权，离线重试不保证成功。重新验证原账号后继续使用选中的资料库，可继续其断点和 NG。切换到另一账号仍按 UID 隔离。

账号菜单的离线资料包导出包含当前账号归档、已保存资源、断点和 NG，排除 Cookie、SESSDATA 和机器配置。ZIP 导出使用 ZIP32，导入支持 stored/deflate；超过文件数或大小限制会提示分批处理。导入会检查路径、账号、资料库归属和校验值，已有断点或 NG 冲突时保留本机版本并提示，不静默覆盖。

资料库标识保存在 `archive-v1/.library.json`，不随目录移动变化。运行状态按 `checkpoints/<library_id>/`、`ng/<library_id>/` 隔离，消息任务使用 `library_id + UID`，不再保存绝对 `archive_root`。旧状态在归属校验通过后迁移并备份到 `migrations/legacy-state/`。`config.json` 不再读写 `last_dir`，文件对话框使用当前导出目录。
